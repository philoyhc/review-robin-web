Interop proof of concept

One click turns this mock exercise into a draft session in Review Robin, populated with its reviewers and reviewees, and opens the session in a new tab. A model for applications that hand their review to Review Robin, such as ApplyDesk.

Create in Review Robin

Creates a draft session owned by you, with the rosters below. You need to be a Review Robin operator. Either the whole session is created or nothing is; if Review Robin refuses, the reason shows here.

Nothing else happens: no assignments, no invitations, no email. The draft waits for you in Review Robin.

Sent to Review Robin

The sessions this browser created. For each, read its live status, or fetch its submitted answers as CSV, keyed by application ID. Both ask Review Robin as you, so you need to operate that session there.

Kept in this browser only; clearing it forgets the list, not the sessions. Nothing here changes anything in Review Robin.

What each read shows

Status

Review Robin's own readings of the session, as its pages label them (status version 3). A failed check shows unavailable, never old counts or zero.

State
Draft, Validated, Activated, Closed or Archived, as Review Robin shows it
Status row
The row on every session page: the four rosters, instruments set up, assignments, invitations, responses
Workflow
The Workflow card: whether setup is complete, and the actions it offers now
Validation
The Validate page's issues, read without validating
Instruments
Each one, and whether it is set up
Progress
Monitoring's summary; provisional while an instrument is not set up
Schedule
Activation, deadline and release, as stored
Per person
Monitoring's reviewer and reviewee tables, folded

Results

results.csv: one row per submitted answer, with ReviewerEmail, RevieweeEmail (the application ID), InstrumentSeq, FieldKey, the labels, ResponseType, Value as stored and SubmittedAt. Saved drafts are not included.

completion.csv: one row per assignment and where it stands: not started, in progress or submitted.
