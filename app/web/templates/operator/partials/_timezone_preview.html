{# A timezone change keeps the instants — progressive enhancement, shared by the Create Session form and Session Home's details card (findings L8, author's ruling). As the operator picks a zone, every `datetime-local` box that holds a value is re-rendered as the same instant's wall-clock in the new zone, so a Save stores the instants the boxes showed before the change. Context (all optional, Create's ids by default): - `tz_input_id` — the Timezone field (a GMT-prefixed label, e.g. "GMT+8 Asia/Singapore", or a bare IANA name). - `tz_box_ids` — the date boxes it governs. A box may carry `data-tz-utc`, its stored instant as UTC wall-clock, so a seeded value in the repeated hour after a DST fall-back converts as the instant it is rather than the first reading of its text. Without script the boxes keep their text and the server keeps each box still holding its seeded text (`_apply_session_config_form`). #}
