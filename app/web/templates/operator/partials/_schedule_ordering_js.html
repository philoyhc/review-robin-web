{# Checks the ordering chain on the four schedule date-time fields as the operator types: ``scheduled_activate_at ≤ deadline ≤ responses_release_at < responses_release_until``, each pair checked only when both of its boxes hold a time, as the server's ``scheduled_events.validate_schedule_ordering`` does, with its wording. A pair out of order marks the later box invalid (``setCustomValidity``), so the browser's form-validity check stops the submit and names the problem there; the server re-runs the check as the load-bearing gate. The calendar picker behind each field gets its neighbors as ``min`` / ``max``, so it offers only in-order times. The boxes are 24-hour text fields (segment 19X Item 6); their text compares in time order once the separator is one form, as ``YYYY-MM-DDTHH:MM``. Used by ``session_new.html`` (the create form). The Session Home config card (#session-config, 18R Item 4) does not run it; ``validate_schedule_ordering`` is the gate for both. #}
