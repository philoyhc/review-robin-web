{# Owners stager — 19S Item 9 Part A, written for Item 10 to reuse. Turns an Owners card's one-at-a-time picker into a **staged** editor: Add owner appends a row to the owners table and Remove takes one out, and nothing is written until the form's own save — Create session on the Create page, the Owners card's Save on Session Home (Item 10). Each staged row carries a hidden input bound to that form, so the rows *are* the owner set the save receives. The card declares its wiring; the script hard-codes no page: [data-owners-stager] the card data-owners-form="
" the form the rows submit with data-owners-name="owners" the field name (default "owners") [data-owners-table] the owners table [data-owners-email] the picker's email input [data-owners-add] the Add owner button [data-owners-remove] a row's Remove (a row without one is fixed, e.g. the creator on Create) data-owners-self="" on the card: the signed-in operator; removing their own row asks first Three rules for every card, from Session Home (19S Item 10, author's rulings, 2026-09-23), harmless on Create: - **The last owner cannot be removed**: whenever one owner row is left, every Remove is disabled. The server refuses an empty set too. - **Removing yourself asks first**, at the click — you lose access to the session once it saves. Cancelling the dialog keeps the row. - **The form's reset restores the rows it was rendered with**, so Session Home's Cancel (a ``type="reset"`` button) undoes staging. **The staging buttons ship ``hidden``** and are shown here, because without JavaScript they would do nothing (19S Item 10). **Without JavaScript** the email input keeps its own ``name`` and ``form=``, so the one address typed there submits with the page. With JavaScript that still holds for an address typed and never added, which is kept rather than silently dropped. Rows are built with ``createElement`` and ``textContent`` — never ``innerHTML`` — because the email is operator-typed. Every change dispatches a bubbling ``change`` event, so a card that gates its Save on a change (Session Home's) sees it; Create ignores it. #}
