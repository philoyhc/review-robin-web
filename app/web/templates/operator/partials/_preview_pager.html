{# Row pager for the seven roster-bearing tables (Segment 19J.5). Rendered twice per page — once where the count line sits, above the table, and once directly below it. A 200-row table is several screens tall, and a pager only at the top makes the operator scroll back to use it. ``pager`` is a ``views.Pager`` or ``None``; ``None`` means one page and no strip, decided in ``views.build_pager``. The route suppresses it entirely while a search or status filter is active — the operator's own partition of the roster wins, and the count line speaks for that view instead. ``pager_url_base`` is the path the range links point at. All seven routes pass one unconditionally; the inert third branch this macro used to carry — a ```` for an unset base — was the scaffold rung's, and came out at 19J.7 rung 4 once it was measured to be unreachable. Restyling a state no page can render is worse than not having it. Every cell but the current one is an ordinary link, and looks like one: the reserved accent shade belongs to things you can act on, and the current cell is the one here that cannot be. It is marked by weight instead (``spec/ui_elements.md`` §10). ``pager_anchor`` is the id a range link lands on. It sits on the **table card** in the including template, not on anything here: the card's top edge is what the operator needs to see, with the column chips and this strip inside it and the new rows beneath. Two earlier targets were wrong and are worth recording. The *table* put its header flush at the viewport top with the page links 31px above the fold. The *top strip* fixed the links but cropped the chip row and the card's own boundary, so the page read as starting mid-card. Turning a page is still a full navigation; the fragment only decides where the browser stops.
